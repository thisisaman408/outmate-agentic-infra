 1. OVERVIEW & PRODUCT GOALS
================================================================================

Outmate Visitor Tracker is a production-grade B2B website deanonymization system.
It identifies the company and/or person behind each anonymous website visit using
a multi-layer IP enrichment pipeline — similar in concept to RB2B and Warmly.ai
but built entirely on our own stack with no third-party data-cooperative dependency.

Core user value:
  - Know WHICH companies are visiting your website right now (company-level)
  - Know WHO specifically is browsing (person-level, when email is captured)
  - See WHAT pages they visited, HOW LONG they stayed, WHERE they clicked
  - Get REAL-TIME alerts when hot accounts hit key pages
  - Understand BUYING INTENT via multi-signal behavioral scoring

Tech stack (unchanged):
  Backend  : FastAPI + Celery + Redis + PostgreSQL (Supabase)
  Frontend : Next.js (App Router) + shadcn/ui + SSE
  Queue    : Celery + Redis (async enrichment)
  Pixel    : Vanilla JS beacon (pixel.js v2.2)

 3. DATABASE SCHEMA (LIVE)
================================================================================

-- site_configs: one row per customer org
CREATE TABLE site_configs (
    org_id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    pixel_key      VARCHAR(255) UNIQUE NOT NULL,
    domain         VARCHAR(255),
    icp_filters    JSONB DEFAULT '{}',         -- per-org ICP weight overrides
    webhook_urls   JSONB DEFAULT '[]',
    webhook_secret VARCHAR(64),                -- auto-generated, HMAC signing
    isp_allowlist  JSONB DEFAULT '[]',         -- corporate VPN ISP overrides
    anonymize_ips  BOOLEAN DEFAULT false,      -- GDPR: mask last IP octet
    gdpr_mode      BOOLEAN DEFAULT false,      -- full GDPR compliance mode
    created_at     TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- visits: one row per page view
CREATE TABLE visits (
    id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    org_id           UUID REFERENCES site_configs(org_id) ON DELETE CASCADE,
    ip               INET NOT NULL,
    url              TEXT NOT NULL,
    referrer         TEXT,
    user_agent       TEXT,
    intent_score     FLOAT DEFAULT 0.5,
    resolution       JSONB,                    -- full enrichment result (see §4)
    matched          BOOLEAN DEFAULT FALSE,
    enrichment_status VARCHAR(20) NOT NULL DEFAULT 'done',  -- processing|done|failed
    created_at       TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- visitor_sessions: groups page views into logical sessions (30-min gap)
CREATE TABLE visitor_sessions (
    id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    org_id           TEXT NOT NULL,
    visitor_id       TEXT NOT NULL,
    session_start    TIMESTAMP WITH TIME ZONE NOT NULL,
    session_end      TIMESTAMP WITH TIME ZONE NOT NULL,
    page_count       INTEGER DEFAULT 1,
    total_dwell_ms   BIGINT DEFAULT 0,
    avg_scroll_depth FLOAT DEFAULT 0,
    total_cta_clicks INTEGER DEFAULT 0,
    entry_url        TEXT,
    exit_url         TEXT,
    referrer         TEXT,
    predicted_persona TEXT,
    buying_stage     TEXT,
    engagement_score INTEGER DEFAULT 0
);

-- identity_nodes: cross-session identity graph (one node per visitor_id)
CREATE TABLE identity_nodes (
    id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    visitor_id     VARCHAR(64) UNIQUE,
    ip             INET,
    email          VARCHAR(255),
    full_name      VARCHAR(255),
    phone          VARCHAR(50),
    linkedin_url   VARCHAR(512),
    job_title      VARCHAR(255),
    company_name   VARCHAR(255),
    company_domain VARCHAR(255),
    raw_data       JSONB DEFAULT '{}',         -- stores fingerprint for cross-org matching
    sources        JSONB DEFAULT '[]',
    pixel_key      VARCHAR(255),
    first_seen_at  TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    last_seen_at   TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- alerts: webhook delivery audit trail
CREATE TABLE alerts (
    id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    visit_id     UUID REFERENCES visits(id),
    webhook_type VARCHAR(50),
    status       VARCHAR(20),                  -- pending|success|failed|failed_final
    payload      JSONB,
    created_at   TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

PERFORMANCE INDEXES:
  ix_visits_org_matched_partial    ON visits(org_id, created_at DESC) WHERE matched = true
  ix_visits_fingerprint_expr       ON visits((resolution->>'fingerprint')) WHERE ...NOT NULL
  ix_visits_visitor_id_expr        ON visits((resolution->>'visitor_id')) WHERE ...NOT NULL
  ix_identity_nodes_fingerprint_expr ON identity_nodes((raw_data->>'fingerprint')) WHERE ...NOT NULL
  ix_identity_nodes_ip_text        ON identity_nodes(ip)

 4. ENRICHMENT PIPELINE (step-by-step)
================================================================================

Each step is independent and best-effort (never throws — only warns on failure).
The pipeline builds a `resolution` JSONB object that is stored in visits.resolution.

resolution shape:
{
  "ip":              string,
  "company":         string | null,       -- canonical company name
  "domain":          string | null,       -- company domain (e.g. "acme.com")
  "geo":             { city, region, country, lat, lon, timezone, is_mobile, is_proxy },
  "confidence":      float (0.0–1.0),
  "tier":            "person" | "company" | "noise" | "unknown",
  "bot_score":       int (0–100),
  "email":           string | null,
  "full_name":       string | null,
  "phone":           string | null,
  "linkedin_url":    string | null,
  "job_title":       string | null,
  "decision_makers": [...],              -- ContactOut DMs for the domain
  "explorium":       { firmographics },
  "behavioral":      { persona, confidence, engagement_score, buying_stage, ... },
  "icp_score":       int (0–100),
  "logo_url":        string | null,
  "ptr_hostname":    string | null,
  "source_site":     string | null,
  "scroll_depth":    float | null,       -- pixel v2.1+
  "cta_clicks":      int | null,         -- pixel v2.1+
  "page_title":      string | null,      -- pixel v2.2+
  "page_h1":         string | null,      -- pixel v2.2+
  "connection_type": string | null,      -- pixel v2.2+
  "_sources":        string[],           -- list of sources that contributed data
  "_mx_unverified":  bool | null,        -- true if domain failed MX check
  "retrolinked":     bool | null,        -- true if this visit was backfilled
}

── STEP -1: IDENTITY GRAPH LOOKUP ─────────────────────────────────────────────
File: visitor_enrich.py → _step_identity_graph_lookup()

Resolution cascade (first match wins):
  1. Exact visitor_id match        — same browser, same org (0.85 confidence)
  2. Cross-org fingerprint match   — same browser fingerprint seen on any org's
                                     site before. Raw_data->>'fingerprint' index.
                                     Re-uses full identity — zero API cost.
                                     (Confidence: 0.85, marked _cross_org=True)
  3. /24 subnet match              — different device, same corporate NAT block.
                                     Returns COMPANY DATA ONLY (not personal).
                                     Confidence: 0.60
  4. Exact IP match                — same IP seen before
  5. Email match                   — email previously captured for this visitor

── STEP -0.5: PTR REVERSE DNS ──────────────────────────────────────────────────
File: visitor_enrich.py → _step_ptr_lookup()

socket.gethostbyaddr(ip) with 3s timeout.
Corporate networks frequently set PTR records: "vpn.televentures.com"
Logic:
  - Skip if is_isp_or_cloud(hostname) — filters "broad.89.isp.net" noise
  - Extract registered domain: "vpn.acme.com" → "acme.com"
  - Extract company hint from subdomain: "vpn.acme.com" → company hint "Acme"
  - Detects residential patterns via _PTR_RESIDENTIAL_RE (dsl/cable/dhcp/pool)
  - Detects corporate patterns via _PTR_CORPORATE_RE (vpn/corp/hq/egress) → +0.10 confidence
Cost: Free, no API. Adds confidence 0.45–0.65

── STEP 0: ip-api.com GEO ───────────────────────────────────────────────────────
File: visitor_enrich.py → _step_ipapi()

Fields: country, city, region, lat/lon, timezone, isp, org (AS), asname, mobile, proxy, hosting
Extracts company from "AS12345 Company Name" → strips AS prefix.
Skips result if is_isp_or_cloud() or is_mobile or is_hosting.
Caches ASN → company in Redis for 24h (avoids repeated lookups for same corporate WAN).
Rate limit: 45 req/min (free). Confidence: 0.20–0.35

── STEP 1: IPinfo ───────────────────────────────────────────────────────────────
File: visitor_enrich.py → _step_ipinfo()

Requires IPINFO_TOKEN. Uses ipinfo-python SDK.
Returns: org, hostname, country_name. Stores in ipinfo_company for agreement booster.
Confidence: 0.30–0.55

── STEP 2: Enrich.so IP → Company ──────────────────────────────────────────────
File: visitor_enrich.py → _step_enrich_so_ip()

GET https://api.enrich.so/v1/api/ip-to-company-lookup?ip=X
Returns: companyName, domain. Skips ISP/cloud results.
Applies _normalize_company_name() before storing.
Confidence: 0.70

── STEP 2.5: MX DOMAIN VALIDATION ──────────────────────────────────────────────
File: visitor_enrich.py → _validate_mx_domain()

dns.resolver.resolve(domain, "MX") with 3s timeout.
Purpose: PTR and ip-api sometimes return hostnames that look like domains
  (e.g. "broad.tata.net.in") but have no MX records and aren't real company domains.
Logic:
  - If domain has no MX records AND confidence < 0.65 → cap confidence at 0.35,
    mark _mx_unverified=True
  - If domain has MX records → boost confidence to 0.55

── STEP 3: EMAIL ENRICHMENT (form-capture path only) ──────────────────────────
Files: _step_enrich_so_email() → _step_bettercontact() → _step_contactout_email()

Only runs when pixel captured an email via identify() or form intercept.
Never uses login-session emails.
Chain: Enrich.so person → BetterContact → ContactOut (each fills gaps the previous missed)
Data: full_name, phone, linkedin_url, job_title, company_domain
Confidence: 0.75–0.85

── STEP 4: ContactOut DM LOOKUP ────────────────────────────────────────────────
File: visitor_enrich.py → _step_contactout_dm()

domain → decision makers with email + LinkedIn.
Returns top 5 DMs sorted by seniority (C-suite first).
Stored in resolution["decision_makers"] — supplementary, never overwrites direct identity.

── STEP 5: Explorium FIRMOGRAPHICS ─────────────────────────────────────────────
File: visitor_enrich.py → _step_explorium()

Search by domain (preferred) or company name.
Returns: industry, employee_count_range, revenue_range, headquarters, linkedin_url, technologies.
Applies _normalize_company_name() on result.
Always overwrites weaker company name sources when it fires.
Confidence: 0.80–0.90

── STEP 5b: Hunter.io ───────────────────────────────────────────────────────────
File: visitor_enrich.py → _step_hunter_io()
Fallback: domain → email pattern (when no person email yet).

── STEP 5c: Clearbit COMPANY ────────────────────────────────────────────────────
File: visitor_enrich.py → _step_clearbit_company()
Requires CLEARBIT_API_KEY. Firmographic fallback after Explorium.
Confidence: 0.75

── STEP 5.5: IP RDAP ────────────────────────────────────────────────────────────
File: visitor_enrich.py → _step_rdap_lookup()

GET https://rdap.org/ip/{ip}
Modern replacement for WHOIS. Returns registrant org for the IP block.
Skips if company already found with confidence >= 0.60.
Applies _normalize_company_name(). Confidence: 0.50
Cost: Free, no API key.

── STEP 5.6: DOMAIN RDAP ────────────────────────────────────────────────────────
File: visitor_enrich.py → _step_domain_rdap()

GET https://rdap.org/domain/{domain}
Queries the domain registry (not the IP block registry).
The registrant org IS legally the company — highest-fidelity free source.
Only runs for MX-verified domains (_mx_unverified is not True).
Parses vCard fn/org fields from registrant entity.
Confidence: 0.65. Cost: Free, no API key.

── STEP 7: MULTI-SOURCE AGREEMENT BOOSTER ───────────────────────────────────────
File: visitor_enrich.py → _boost_confidence_by_agreement()

Collects normalized company name candidates from all 7 sources:
  ip-api, IPinfo, IP RDAP, Domain RDAP, Enrich.so, Explorium, Identity graph

Uses _normalize_company_name() to strip legal suffixes before comparison
(so "Televentures Ltd." == "Televentures Limited" == "Televentures").

Agreement rules:
  2 sources agree  → confidence = max(current, 0.78)
  3+ sources agree → confidence = max(current, 0.90)
  Canonical name   → picked from highest-priority source (Explorium > Enrich.so > ip-api)

This is the key accuracy booster for company-level identification —
multiple independent sources agreeing eliminates false positives.

── STEP 8: IDENTITY GRAPH STORE ─────────────────────────────────────────────────
File: visitor_enrich.py → _step_identity_graph_store()

Upserts identity_nodes with all resolved fields.
Stores browser fingerprint in raw_data->>'fingerprint' for future cross-org matching.
On update: fills empty fields only; email from form-capture always wins.

COMPANY NAME NORMALISATION (_normalize_company_name):
Strips legal suffixes before storing and comparing:
  "Televentures Ltd." → "Televentures"
  "ACME CORPORATION" → "ACME"
  "Foo Pvt. Ltd." → "Foo"
Patterns covered: Ltd, Limited, Inc, Corp, Corporation, LLC, LLP, GmbH, Pvt Ltd,
  Pte Ltd, S.A., S.R.L., B.V., A.G., PLC, Co., & Co., Holdings, Group

ASN → COMPANY REDIS CACHE (24h TTL):
When ip-api returns an AS number for a corporate IP, the resolved company is
cached at key "asn:{asnum}". Future IPs with the same ASN are identified instantly
with zero API calls — especially effective for orgs with a dedicated corporate ASN.

REDIS DOMAIN CACHE (72h TTL):
When full domain-level enrichment succeeds, the result is cached at
"enrich:domain:{domain}". Future visitors from the same company domain skip
steps 3–5.6 entirely and get the cached firmographic data immediately.

 5. BEHAVIORAL INTELLIGENCE ENGINE
================================================================================

File: services/behavioral_scoring.py

Predicts the job role (persona) and buying stage of each anonymous visitor
from their aggregated page journey. Runs per-visitor_id after enrichment.

PERSONAS (8 categories):
  engineering, sales, executive, marketing, hr, product, finance, unknown

SIGNALS SCORED (10 dimensions):
  1.  Page Topic Taxonomy    — URL path segments mapped to persona weights
  2.  Page Meta Signals      — <title> and <h1> text (pixel v2.2+) mapped to 12 B2B patterns
  3.  Dwell Time Weighting   — deep dwell amplifies topic score (2x for >60s)
  4.  Scroll Depth           — high scroll (>75%) amplifies topic signal by 40%
  5.  CTA Click Tracking     — clicks on pricing/demo/contact buttons
  6.  Visit Frequency        — repeat visits boost engagement
  7.  Session Depth          — more unique pages = higher intent
  8.  Form Interaction       — email captured = max buying signal
  9.  Referrer Signals       — LinkedIn/GitHub/G2 → persona hint
  10. Time-of-Day Patterns   — business-hours visits weighted higher

NEW in v2.2:
  - Visit Velocity (pages/hour) — high velocity signals active research mode
    compute_visit_velocity(): measures pages/hour in last 10 visits
    Scoring: ≥12 ph → +5pts, ≥6 ph → +3pts, ≥2 ph → +1pt

  - Engagement Time Decay — 14-day half-life exponential decay
    apply_engagement_decay(): visitors inactive for 2 weeks score 50% lower
    Stale data never zeroes out (minimum score = 1)

  - Page Meta Classification (classify_page_meta()):
    Scores page title + h1 text against 12 B2B keyword patterns
    E.g. "Enterprise Security & Compliance Overview" → executive=0.4, engineering=0.3
    Meta signals worth 70% of URL signals (supplementary, not primary)

ENGAGEMENT SCORE (0–100):
  Visit frequency:   up to 20 pts
  Page depth:        up to 15 pts
  Dwell time:        up to 15 pts
  Form interaction:  up to 15 pts
  Recency:           up to 10 pts
  Referrer quality:  up to  8 pts
  Scroll depth:      up to  7 pts
  CTA clicks:        up to  5 pts
  Visit velocity:    up to  5 pts
  Business hours:    up to  5 pts

BUYING STAGE:
  "decision"      — visited pricing/demo + (form fill or engagement ≥ 60)
  "consideration" — 3+ visits or engagement ≥ 40
  "awareness"     — everything else

RECENCY BOOST:
  Last 5 visits get 1.5× multiplier on all persona scores.
  Visits 6–10 get 1.2× multiplier.
  Older visits get 1.0×.

ICP SCORE (0–100) — per-org configurable:
  Default weights: company(25) + person(20) + industry(15) + headcount(15) +
                   revenue(10) + linkedin(10) + domain(5) = 100
  Per-org overrides via site_configs.icp_filters:
    w_company, w_person, w_industry, w_headcount, w_revenue, w_linkedin, w_domain
  Industry filter: ±10 pts bonus/penalty for target industry match
  Headcount filter: –15 pts if employee count outside min/max range


================================================================================
 6. IDENTITY GRAPH & CROSS-ORG MATCHING
================================================================================

File: visitor_enrich.py + db/models/identity_graph.py

The identity_nodes table is the cross-session memory of the system.
Every enriched visitor with meaningful data gets one node per visitor_id.

RESOLUTION CASCADE (Step -1):
  1. visitor_id    → exact match (most reliable, same browser/org)
  2. fingerprint   → cross-org match via raw_data->>'fingerprint'
                     Expression index: ix_identity_nodes_fingerprint_expr
                     A visitor who filled a form on company A's site is instantly
                     recognized on company B's site — zero API spend.
  3. /24 subnet    → corporate NAT clustering
                     Same /24 block = likely same corporate network.
                     Returns COMPANY DATA ONLY (not personal — different person).
                     Index: ix_identity_nodes_ip_text
  4. exact IP      → same IP seen before
  5. email         → email match

FINGERPRINT STORAGE:
  Pixel sends getFingerprintHash() (canvas + audio + screen + fonts hash).
  Stored in identity_nodes.raw_data->>'fingerprint'.
  Expression index enables O(log n) cross-org lookups.

RETROACTIVE BACKFILL (tasks/visitors.py):
  When a visitor is identified (email/name/company resolved), ALL prior visits
  from the same visitor_id are retroactively patched via one SQL UPDATE:
    Fields patched: email, full_name, company, domain, job_title, linkedin_url, logo_url
  This means: visit history immediately shows full identity, not just the current visit.
  SQL pattern: iterative jsonb_set() chain built dynamically from resolved fields.

COMPANY NAME NORMALISATION:
  Before comparing across sources and before storage, all company names pass through
  _normalize_company_name() which strips 20+ legal-entity suffix patterns.
  Effect: "Televentures Ltd." + "TELEVENTURES LIMITED" + "Televentures" all
  match as the same company → agreement booster fires → confidence 0.90.

NOISE FILTERING:
  is_isp_or_cloud(): keyword filter for 100+ ISP/cloud/hosting names
  Mobile ASN patterns: Jio, Airtel, Vodafone, Vi → is_mobile=True → skip
  Bot score: UA patterns + zero viewport + cloud ASN → bot_score (0–100)
  Hosting flag: ip-api "hosting" field → datacenter IP → tier=noise
  Proxy flag: ip-api "proxy" field → adds to bot_score
  PTR residential regex: dsl/cable/dhcp/pool + IP-in-hostname pattern → skip

ISP ALLOWLIST (per-org):
  Corporate VPN exits often look like ISP IPs.
  site_configs.isp_allowlist: ["cloudflare", "zscaler"] → these are NOT filtered.
  Passed to every is_isp_or_cloud() call in the pipeline.


================================================================================
 8. PIXEL.JS (v2.2)
================================================================================

Files:
  Backend/app/static/pixel.js  — served by FastAPI, canonical source
  Frontend/public/pixel.js     — copy for Next.js dev environment

Embed snippet:
  <script src="https://app.outmate.ai/static/pixel.js?key=YOUR_PIXEL_KEY" async></script>

CAPABILITIES:

Fingerprinting (getFingerprintHash()):
  Canvas pixel rendering + AudioContext output + screen dimensions +
  installed fonts via measureText. SHA-256 hashed. Stored in localStorage
  ("_ot_fp"). Sent as "fp" field on every beacon.

Visitor ID (getVisitorId()):
  UUID v4 generated once per device. Stored in localStorage ("_ot_vid").
  Persists across sessions, pages, and referrer changes.

Email capture (identify(email)):
  Customer calls window.outmateTracker.identify(email) on form submit.
  Email stored in localStorage and appended to next beacon.
  Triggers Enrich.so + BetterContact + ContactOut email enrichment chain.

CTA click tracking:
  MutationObserver watches for buttons/links matching pricing/demo/contact/cta patterns.
  Increments _ctaClicks counter. Reset per page view.

Scroll depth:
  Passive scroll listener. Tracks max scroll % reached on current page (_maxScrollPct).
  Reset per page view.

Dwell time:
  Sent on page unload (visibilitychange → hidden + pagehide).
  Measured from _pageEntryTime. Sent as "leave" action.

NEW in v2.2 — Page meta signals:
  page_title:      document.title (first 120 chars)
  page_h1:         document.querySelector('h1').textContent (first 80 chars)
  connection_type: navigator.connection.effectiveType (e.g. "4g", "wifi")

PAYLOAD SHAPE (POST /api/v1/visitors/track):
{
  action:          "pageview" | "leave",
  url:             string,
  referrer:        string,
  pixel_key:       string,
  email:           string | null,
  visitor_id:      string,
  fp:              string,                 -- fingerprint hash
  viewport_w:      number,
  viewport_h:      number,
  dwell_time:      number | undefined,     -- ms, only on "leave"
  scroll_depth:    number,                 -- 0–100 %
  cta_clicks:      number,
  page_title:      string | undefined,     -- v2.2+
  page_h1:         string | undefined,     -- v2.2+
  connection_type: string | undefined,     -- v2.2+
}

DEDUPLICATION (backend):
  Redis key: "dedupe:{org_id}:{ip}:{domain}" with 30-min TTL.
  Prevents processing the same IP+domain more than once per half-hour.

BOT FILTERING (backend, before Celery enqueue):
  UA missing → +20 bot_score
  UA contains bot/crawler/spider/headless → +50
  Zero viewport → +20
  Cloud ASN → +20
  Datacenter IP → +15
  bot_score ≥ 50 → rejected immediately; ≥ 40 → tier=noise

 10. CELERY TASKS
================================================================================

File: app/tasks/visitors.py

process_visitor_task(org_id, data):
  Bound, max_retries=2, autoretry_for=Exception, retry_backoff=True (max 120s)
  Creates stub visit (enrichment_status='processing') → enriches → updates to 'done'
  On unhandled exception → marks enrichment_status='failed'
  Enrichment status visible in dashboard as spinner/error state.

deliver_webhook(webhook_url, payload, visit_id, alert_id, webhook_secret):
  Bound, max_retries=3
  Signs payload with HMAC-SHA256: X-Outmate-Signature: sha256=<hex>
  Retry schedule: 5s → 60s → 300s
  Fallback: if Celery unavailable, attempts synchronous httpx delivery
  Final failure: sets alert.status='failed_final'

 11. REAL-TIME SSE STREAM
================================================================================

Endpoint:  GET /api/v1/visitors/stream?token=JWT
Transport: Server-Sent Events (text/event-stream)
Channel:   Redis pub/sub on key "visitors:{org_id}"

Event shape:
{
  "type": "visit_created",
  "org_id": string,
  "visit": {
    id, ip, url, referrer, intent_score, matched, created_at,
    resolution, category, company, domain, geo,
    full_name, email, source_site, industry, employee_count_range
  }
}

Reconnection: Frontend uses EventSource with exponential backoff (500ms → 30s max).
Heartbeat: 30s keepalive comment sent to prevent proxy timeouts.
Published by: _publish_visit_event() in tasks/visitors.py after each enrichment.


================================================================================
 12. WEBHOOK DELIVERY (HMAC-SIGNED)
================================================================================

Configured in site_configs.webhook_urls (JSON array of URLs).
Fired for every visit where matched=True.

HMAC Signature:
  Secret: site_configs.webhook_secret (auto-generated 32-byte hex on row creation)
  Header: X-Outmate-Signature: sha256=<HMAC-SHA256(body_bytes, secret.encode())>
  Body: deterministic JSON (no spaces, sorted separators)
  Verification by customer: compare expected_sig with header value using hmac.compare_digest()

Webhook payload:
{
  "event":      "visitor_identified",
  "visit_id":   UUID,
  "ip":         string,
  "url":        string,
  "resolution": { ...full resolution object... },
  "timestamp":  ISO-8601
}

Retry schedule (Celery):  5s → 60s → 300s (3 attempts total)
Audit trail: alerts table (status: pending → success | failed | failed_final)


================================================================================
 13. PRIVACY & GDPR CONTROLS
================================================================================

Per-org settings (site_configs):

anonymize_ips (BOOLEAN):
  When true: last IP octet masked before storage (192.168.1.123 → 192.168.1.0)
  Applied in _process_visitor_data() before visit record is written.

gdpr_mode (BOOLEAN):
  Full GDPR compliance mode — future: auto-delete after 30 days, consent check.

ISP Allowlist (isp_allowlist JSONB array):
  Corporate VPN exits (e.g. Zscaler, Cloudflare Gateway) look like ISPs.
  Add ISP keyword substrings here to prevent them being filtered as noise.

Data deletion:
  DELETE /api/v1/visitors/visits/{visit_id} — removes single visit record (GDPR right to erasure)

IP storage policy:
  IPs stored as INET type in PostgreSQL — never logged in plaintext elsewhere.
  With anonymize_ips=true, the full IP is never written to the DB at all.

 16. PERFORMANCE INDEXES
================================================================================

-- Fast query: all matched visits for an org, newest first
CREATE INDEX IF NOT EXISTS ix_visits_org_matched_partial
  ON visits (org_id, created_at DESC) WHERE matched = true;

-- Cross-org fingerprint dedup (identity graph)
CREATE INDEX IF NOT EXISTS ix_identity_nodes_fingerprint_expr
  ON identity_nodes ((raw_data->>'fingerprint'))
  WHERE raw_data->>'fingerprint' IS NOT NULL;

-- /24 subnet clustering scans
CREATE INDEX IF NOT EXISTS ix_identity_nodes_ip_text
  ON identity_nodes (ip);

-- Fast visitor_id resolution within a visit
CREATE INDEX IF NOT EXISTS ix_visits_visitor_id_expr
  ON visits ((resolution->>'visitor_id'))
  WHERE resolution->>'visitor_id' IS NOT NULL;

-- Fast fingerprint dedup within visits
CREATE INDEX IF NOT EXISTS ix_visits_fingerprint_expr
  ON visits ((resolution->>'fingerprint'))
  WHERE resolution->>'fingerprint' IS NOT NULL;

All indexes are idempotent (CREATE INDEX IF NOT EXISTS) — safe to run on restart.
Applied in main.py startup block.
